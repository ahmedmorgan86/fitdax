# FitDax

تطبيق لياقة ويب متجاوب، عربي/إنجليزي وRTL، بأسود وأخضر كهربائي. الاسم والتصميم الحاليان لا يحتويان كلمة AI، ولا يُستدعى أي نموذج ذكاء اصطناعي.

## البنية

- Next.js 16 على Vercel.
- Supabase Auth، جلسات عبر ملفات ارتباط HTTP-only، والتحقق من المستخدم على الخادم.
- Supabase Postgres مع RLS لكل الجداول العامة، وعمليات حفظ مشروطة برقم النسخة.
- تشفير AES-GCM لملف القياسات والسجلات قبل التخزين، بمفتاح خادمي. ليس تشفيرًا من طرف إلى طرف. لا توجد نسخة صحية دائمة في localStorage.
- لوحة أدمن لتعديل الهوية والدعم والباقات والأسعار والبرامج والتمارين والوجبات. صلاحية الإدارة محكومة بقاعدة البيانات، ولا تعتمد على user_metadata أو ادعاء من المتصفح.
- ربط الأدمن ببريد المالك المتحقق منه: ahmed.morgan2009@gmail.com. يلزم تسجيل الدخول والتحقق من البريد؛ لا توجد كلمة مرور افتراضية.
- لا تعرض لوحة الإدارة البيانات الصحية لمستخدم آخر. المستخدم يعدّل بياناته الشخصية فقط.

## المزايا

Onboarding وموافقة تخزين، قياسات، مكتبة 10 تمارين، برامج أساسية، تسجيل الجلسات، سجل وزن وخصر، غذاء وماء، تقديرات طاقة وأفكار وجبات، تصدير JSON وحذف السجل النشط. يعتمد التخطيط على قوالب وقواعد، ولا يوجد مدرب محادثة أو تحليل وضعية أو ربط ساعات.

Free: مكتبة، برامج أساسية، وتسجيل النتائج. Pro: منطقة التغذية وملخصات التقدم والتخطيط بتفضيلات. الأدمن له وصول كامل دون دفع. Premium باقة مستقبلية غير متاحة للبيع، وليست خدمة ذكاء اصطناعي.

## الدفع — الحالة الحقيقية

الأسعار التجريبية المضبوطة: Pro ‏99 جنيه/شهر أو 799 جنيه/سنة. Premium المستقبلي 199/1499 وغير متاح. يمكن للأدمن تعديلها.

تدعم النسخة طلبات تحويل يدوي بالمحافظ الرقمية وInstaPay، مع مراجعة الأدمن داخل صفحة الدفع. يُثبّت الخادم سعر الباقة وبيانات المستفيد عند إنشاء الطلب. إرسال رقم عملية يجعل الطلب قيد المراجعة فقط. الموافقة محصورة بالأدمن، وتُفعّل المدة مرة واحدة مع سجل تدقيق. مرجع التحويل مرفوض إن تكرر لنفس الوسيلة. لا توجد خصومات أو تجديدات تلقائية أو تحقق بنكي آلي.

رقم المحفظة الذي قدمه المالك موجود في إعدادات الأدمن، والتحصيل معطل افتراضيًا. يجب إدخال اسم المستفيد الصحيح، وتأكيد صلاحية الحساب للتحصيل، وفتح الباقة ثم تفعيل الوسيلة من لوحة الإدارة. عنوان InstaPay IPA لم يقدمه المالك بعد، ولا يُفترض أن رقم المحفظة هو عنوان InstaPay. لا تطلب الواجهة PIN أو OTP أو كشف حساب. لا يوجد رفع صور إيصالات. المطابقة تتم في حساب المستفيد الفعلي، وليست صورة أو ادعاء المستخدم دليل دفع.

تُحفظ بيانات طلبات التحويل منفصلة عن بيانات الصحة، ويقرأ العضو طلباته فقط والأدمن طلبات المراجعة. حذف سجل اللياقة لا يحذف سجل الدفع. لم تعتمد مدة احتفاظ مالية أو سياسة استرداد نهائية؛ يلزم تحديدها قانونيًا قبل التفعيل العام. لم تنفذ دورة دفع بأموال حقيقية. لا توجد بوابة Paymob متصلة أو webhook مالي، ومسار billing القديم يوضح أن الربط الآلي غير متاح.

## التشغيل

Node.js 22.13+، ثم:

```sh
npm ci
cp .env.example .env.local
npm test
npm run build
npm run dev
```

ضع القيم الفعلية في ملف محلي مستبعد من Git أو إعدادات Vercel. لا تضع الأسرار في public أو متغيرات NEXT_PUBLIC. يحتاج FITVERSE_DATA_KEY إلى قيمة hex عشوائية تشفيريًا بطول 64 حرفًا. **لا تغيّر مفتاح الإنتاج دون خطة لفك وإعادة تشفير السجلات؛ فقدانه يمنع قراءة البيانات.** لا توجد حاجة إلى service_role أو مفتاح AI في التطبيق.

التطوير المحلي لا يحتوي هوية أدمن مزيفة أو تجاوز مصادقة. يستخدم Supabase Auth الحقيقي. يلزم ضبط Site URL وعناوين إعادة التوجيه في Supabase، وإعداد SMTP تجاري للتحقق من إرسال البريد لكل المستخدمين. مزوّد البريد الافتراضي مقيد وقد لا يرسل إلا إلى عناوين مخولة لدى المشروع. رابط الدخول يعمل عبر /auth/callback، وواجهة الدخول الحالية تستخدم Google فقط، ولا تعتمد على البريد التجاري للتسجيل. لم يتم الادعاء باختبار وصول البريد الفعلي.

## قاعدة البيانات

المشروع: `pdhugcwfleytfpfjvetq`، داخل مؤسسة المالك، منطقة eu-west-1. ترحيل schema موجود في supabase/migrations. لم تتغير مشروعات Supabase القديمة.

لا تشغّل ملف rls-check.sql على بيانات إنتاج حقيقية دون مراجعة: هو اختبار معاملات ببيانات اصطناعية ومعرفات اختبار، وينتهي بـROLLBACK. يختبر RLS عند تبديل سياق الهوية داخل SQL؛ هذا لا يعوض اختبار تسجيل الدخول من البريد في متصفح حقيقي.

## التحقق

- 10 اختبارات منطق التدريب والطاقة والوجبات.
- 14 اختبارًا للإصدار: الموافقة والعمر ورفض تزوير الأدوار وتشفير المستخدم والتحقق من كتالوج الإدارة والأصل والحجم.
- بناء Next.js ناجح.
- اختبار فعلي في Supabase أثبت: عدم ترقية دور المستخدم عبر metadata، العزل بين الحسابات، منع تعديل الكتالوج لغير الأدمن، منع تفعيل الاشتراك ذاتيًا، تعارض النسخ، رؤية سجل التدقيق للأدمن فقط، والحذف. جميع سجلات الاختبار تراجعت دون حفظ.
- فحص Supabase Security Advisors بعد إنشاء الجداول لم يعرض تنبيهات.
- نسخة الخادم السابقة على Cloudflare اجتازت مسارات متصفح للإعداد والحفظ والتصدير. لا تُعد هذه دليلًا على اكتمال مصادقة Supabase أو لوحة الأدمن في نسخة Vercel. يذكر تقرير الإصدار ما تم اختباره بعد النشر تحديدًا.

لا توجد فيديوهات مرخصة مرفقة؛ الرسوم زخرفية أصلية وليست عرضًا آمنًا للحركات. حقول الوسائط مقفلة على null حتى إدخال محتوى موثق ومراجعته وتوسيع المشغل مع التراخيص والإتاحة.

يلزم قبل الإطلاق التجاري العام: مراجعة مدرب وأخصائي تغذية ومختص قانوني لمصر وعمليات نقل البيانات وإقامة التخزين، اختبار أمني وإتاحة وأجهزة فعلية، تهيئة البريد، وتأكيد صلاحية حساب التحصيل وسياسة الاسترداد ومراجعة إجراءات المطابقة واختبار تحويل فعلي. إشعار الخصوصية الحالي يصف النسخة بصدق ولا يمثل شهادة امتثال. حذف بيانات اللياقة لا يحذف حساب المصادقة أو ملفات التصدير أو نسخ المزود الاحتياطية.

## التسجيل والدخول بجوجل فقط

واجهة واحدة بزر Google للتسجيل والدخول. أُزيلت مسارات البريد وكلمات المرور وOTP والاستعادة وتغيير كلمة المرور. يرفض /api/auth هذه الإجراءات، ولا يقبل إلا google. لا توجد كلمات مرور يديرها التطبيق. ويتحقق الخادم من هوية Google مؤكدة قبل السماح بوظائف التطبيق؛ الجلسات القديمة التي لا تحمل هوية Google لا تحصل على وصول من واجهات التطبيق.

Google OAuth Client موجود ومربوط بـSupabase، ومزوّد Google مفعّل والبريد معطّل. Google في وضع In production؛ اعتماد العلامة لدى Google ليس مؤكدًا. رابط الإنتاج https://fitdax-app.vercel.app وعنوان العودة /auth/callback. معرّف مشروع Google الداخلي fitverse-512218، ومعرّف Supabase pdhugcwfleytfpfjvetq مستمران لحفظ الاتصال والبيانات. نجح اختبار الدخول الحقيقي لحساب المالك عبر Google والعودة إلى التطبيق، وقراءة صلاحية الأدمن وحفظ الكتالوج في Supabase.

الأسماء الداخلية للجداول ومسارات /fitverse ومتغيرات FITVERSE_ محفوظة للتوافق، ولا تغيّر هوية المنتج الظاهرة. الدفع اليدوي يظل معطّلًا حتى استكمال اسم المستفيد وبيانات InstaPay والتحقق الفعلي. مراجعة المحتوى الرياضي والتغذوي والتراخيص والسياسات التجارية لم تكتمل.
